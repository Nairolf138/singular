# Singular v0.1.0

Première release du paquet Python pour les parcours CLI `stable` du
[registre des capacités](../README.md#registre-des-capacités-stable) : création
et sélection d'une vie, profil de démarrage `assistant`, consultation de l'état,
conversation locale avec le provider factice `dummy`, diagnostic et politique de
rétention en aperçu. Un rapport nécessite un run existant.

## Installation

Python 3.11 ou plus récent. Téléchargez `singular-0.1.0-py3-none-any.whl` ou
`singular-0.1.0.tar.gz` depuis la [release GitHub](https://github.com/Nairolf138/singular/releases/tag/v0.1.0),
vérifiez son SHA-256 dans `SHA256SUMS`, puis installez le fichier téléchargé :

```bash
sha256sum -c SHA256SUMS
python -m venv .venv
.venv/bin/python -m pip install ./singular-0.1.0-py3-none-any.whl
SINGULAR_ROOT="$(mktemp -d)" .venv/bin/singular lives create --name Lumen --starter-profile assistant
```

Sur Windows, utilisez `.venv\\Scripts\\python` et `.venv\\Scripts\\singular`.
La vérification `sha256sum -c` suppose que les trois fichiers téléchargés se
trouvent dans le même répertoire. Le provider `dummy` renvoie un écho factice :
aucun modèle LLM réel n'est fourni avec le paquet.

## Périmètre

| Statut | Fonctionnalités de cette version | Engagement |
| --- | --- | --- |
| `stable` | Parcours CLI recensés dans le registre canonique, avec leurs prérequis et tests | Compatibilité et corrections de régression sur ces parcours. |
| `experimental` | Évolution, mutations, quêtes, mémoire avancée, reproduction, cycle vital avancé | Interfaces et données susceptibles de changer ; la mutation de code requiert un sandbox OCI. |
| `optional` | Dashboard, YAML, visualisation, providers OpenAI/locaux, ROS2, GPIO, services systemd/Docker | Dépendances ou services externes à installer et configurer séparément ; pas de garantie d'intégration par le wheel de base. |
| `target-only` | Objectifs AGI, jalons cognitifs et plans de reprise du dashboard | Spécifications ou projets, sans fonction livrée garantie. |

Cette version ne démontre ni conscience, ni apprentissage général, ni autonomie
sur machine réelle. Ne lancez pas d'évolution sur du code non fiable sans le
runtime OCI compatible requis par le projet.

## Vérification de publication

Le tag doit pointer vers un commit de `main`. Le workflow `Release v0.1.0`
teste les parcours CLI stables sous Python 3.11 et 3.12, construit l'archive
source et le wheel à partir de ce commit, puis vérifie l'installation et les
commandes depuis chacun des deux artefacts hors du dépôt. Il attache les deux
distributions et `SHA256SUMS` à la GitHub Release uniquement après succès de
ces contrôles. Les jobs de la CI générale couvrent aussi les intégrations et
les fonctions expérimentales ; ils sont suivis séparément et ne constituent
pas une garantie pour cette release limitée. Aucune publication PyPI n'est
prévue pour v0.1.0.
